# 19. Channel 4 — Noise

Channel 4 (`9e6164c`) is the odd one out: it has no pitch, no
waveform, no duty cycle. It produces a buzzing/hissing noise, by rapidly
flipping between two volume levels in a pattern that *looks* random but
is actually completely deterministic — generated by something called a
**Linear Feedback Shift Register (LFSR)**.

## A 15-bit register that "shifts" its way to pseudo-randomness

```rust
// src/audio/noise_channel.rs
#[derive(Default)]
pub struct NoiseChannel {
    pub enabled: bool,
    pub freq_timer: u32,
    // ... length/envelope fields, same shape as Channel (Chapter 16)
    pub clock_shift: u8,
    pub clock_divider: u8,
    pub short_mode: bool,
    pub lfsr: u16,
}
```

An LFSR is just a number (`lfsr`, here 16 bits wide though only 15 are
really used) that, every so often, computes one new bit from its
*current* bits, shifts everything over by one position, and inserts that
new bit at the top. Doing this repeatedly produces a long sequence of
bits that passes casual tests for randomness (it won't obviously repeat
for a very long time), while still being 100% reproducible given the same
starting value and the same sequence of operations — exactly what you
want in a deterministic emulator: the "random" noise channel must still
sound bit-for-bit identical to real hardware every time, including
exactly the same "random" sequence, since any accurate emulator (and
real hardware!) is only pseudo-random.

## The actual shift-and-feedback step

```rust
pub fn tick(&mut self) {
    self.freq_timer = self.freq_timer.saturating_sub(1);
    if self.freq_timer == 0 {
        let divider = if self.clock_divider == 0 { 8 } else { self.clock_divider as u32 * 16 };
        self.freq_timer = divider << self.clock_shift;

        // bit 0 XNOR bit 1 (1 if they're equal, 0 otherwise) feeds back into bit 15
        let bit0 = self.lfsr & 0x01;
        let bit1 = (self.lfsr >> 1) & 0x01;
        let res = if bit0 == bit1 { 1 } else { 0 };
        self.lfsr = (self.lfsr & 0b0111_1111_1111_1111) | (res << 15);

        // "short mode": also copy that same feedback bit into bit 7
        if self.short_mode {
            self.lfsr = (self.lfsr & 0b1111_1111_0111_1111) | (res << 7);
        }

        // shift everything right by one; the new bit 0 selects the output
        self.lfsr = self.lfsr >> 1;
    }
}
```

Step by step: take the two lowest bits of the current `lfsr` value,
compare them (`1` if equal, `0` if different — this comparison is called
XNOR), and feed that single result bit back in at the *top* of the
register (bit 15), before shifting the whole thing right by one. The
channel's actual audio output, at any instant, is simply "is bit 0 of
`lfsr` set" — a rapidly, pseudo-randomly flipping single bit, which is
exactly what noise sounds like.

"Short mode" (`NR43`'s bit 3) additionally copies that same feedback bit
into bit 7, which shortens the LFSR's effective cycle length, producing a
noticeably different, more "metallic" texture than the default "long
mode" — a real example of a single configuration bit meaningfully
changing a channel's timbre, not just its pitch or volume.

## Why the frequency calculation looks different from channels 1-3

```rust
let divider = if self.clock_divider == 0 { 8 } else { self.clock_divider as u32 * 16 };
self.freq_timer = divider << self.clock_shift;
```

Square and wave channels (Chapters 16-18) pick their pitch from one
linear "period" value. Noise instead derives its tick rate from two
separate fields multiplied together in a slightly unusual way: a small
base divisor table-like rule (`clock_divider == 0` is special-cased to
mean 8, otherwise it's `clock_divider * 16`), then left-shifted by
`clock_shift`. This isn't something you derive from first principles —
it's a documented register format you implement and verify, the same
spirit as `DAA` back in Chapter 4.
